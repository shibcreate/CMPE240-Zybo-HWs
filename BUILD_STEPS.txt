================================================================================
  Real-Time Mono Audio Spectrum Analyzer with HDMI Visualization
  CMPE240 - Zybo Z7-10 | Build Steps (project branch)
================================================================================

PREREQUISITES
  - Vivado 2025.2.1 (or compatible 2025.2.x)
  - Vitis Unified IDE 2025.2
  - Zybo Z7-10 board connected via USB
  - HDMI monitor + cable connected to HDMI TX on the Zybo
  - Audio source with 3.5mm cable connected to LINE IN (J6) on the Zybo
  - Digilent board files installed in Vivado
    (Settings > IP > Repository > Board Files should include Zybo Z7-10)

================================================================================
  PROJECT OVERVIEW
================================================================================

This project is a real-time audio spectrum analyzer that:
  - Captures audio via the SSM2603 codec (I2S, 48kHz, 24-bit stereo)
  - Mixes stereo to mono in PL hardware
  - Computes 256-point FFT in PL (Xilinx FFT LogiCORE IP)
  - Transfers FFT data to PS via AXI DMA with interrupts
  - PS computes magnitudes, applies log-frequency binning, and renders
    a 24-bar spectrum visualization to a 640x480 HDMI framebuffer
  - Visualization features: 3 frequency groups (Bass/Vocal/High),
    per-group gain normalization, peak-hold dots, smooth decay,
    mirror reflections, top glow, gradient background, title text,
    and a reactive color bar

Hardware controls:
  - BTN3: Start/stop audio capture and spectrum display
  - SW0:  Toggle audio line-out passthrough (hear what you analyze)
  - SW1:  Toggle digital gain boost (1.5x) for quiet songs

================================================================================
  WHY A FRESH CLONE DOESN'T "JUST BUILD"
================================================================================

The .gitignore excludes large generated files:
  - Vivado: .runs/, .cache/, .hw/, .ip_user_files/, and IP outputs
    under hw.gen/ip/ and hw.gen/ipshared/
  - Hardware: *.bit, *.xsa (bitstream and hardware export)
  - Vitis: build/, BSP libs, FSBL, *.elf (all build output)

The HDL wrapper and block design metadata ARE tracked in hw.gen/hdl/,
so you do NOT need to recreate the wrapper after cloning.

The Vitis workspace under my_vitis_ws/ contains HARDCODED ABSOLUTE PATHS
in files like vitis-comp.json and app.yaml. You MUST create a fresh Vitis
workspace (see Steps 8-13 below).

================================================================================
  STEP 1: CLONE THE REPO
================================================================================

  git clone -b project https://github.com/shibcreate/CMPE240-Zybo-HWs.git
  cd CMPE240-Zybo-HWs

================================================================================
  STEP 2: OPEN THE VIVADO PROJECT
================================================================================

  - Open Vivado 2025.2.1
  - File > Open Project
  - Navigate to: Zybo-Z7-10-DMA-hw/hw/hw.xpr
  - Click OK
  - Vivado may show warnings about missing run directories -- this is expected.
    It will automatically recreate .cache/, .runs/, etc.
  - If Vivado asks to update the project path, click YES/OK.

================================================================================
  STEP 3: GENERATE BLOCK DESIGN OUTPUT PRODUCTS
================================================================================

  - In the Sources panel, expand Design Sources
  - Right-click on "system" (system.bd) block design
  - Click "Generate Output Products"
  - Select "Out of context per IP" generation, click Generate
  - Wait for it to complete (a few minutes)
  - This regenerates the IP cores under hw.gen/ip/ and hw.gen/ipshared/

  NOTE: The HDL wrapper (system_wrapper.v) is already included in the repo
  under hw.gen/hdl/. You do NOT need to create a new one.

================================================================================
  STEP 4: RUN SYNTHESIS
================================================================================

  - Click "Run Synthesis" in the Flow Navigator (left panel)
  - Or in the Tcl console: launch_runs synth_1 -jobs 16
  - Wait for synthesis to complete (~5-10 min)

  IF SYNTHESIS FAILS with:
    ERROR: [Vivado 12-3280] Incremental checkpoint file
    '...system_wrapper.dcp' does not exist.
  Run these commands in the Vivado Tcl console:
    reset_run synth_1
    set_property AUTO_INCREMENTAL_CHECKPOINT 0 [get_runs synth_1]
    launch_runs synth_1 -jobs 16

================================================================================
  STEP 5: RUN IMPLEMENTATION
================================================================================

  - When synthesis completes, select "Run Implementation" and click OK
  - Or in the Tcl console: launch_runs impl_1 -jobs 16
  - Wait for implementation to complete (~5-10 min)

================================================================================
  STEP 6: GENERATE BITSTREAM
================================================================================

  - When implementation completes, select "Generate Bitstream" and click OK
  - Wait for bitstream generation to complete (~2-5 min)

================================================================================
  STEP 7: EXPORT HARDWARE (.XSA) AND PATCH GP1 BUG
================================================================================

  7a. Export Hardware:
  - File > Export > Export Hardware
  - Select "Include bitstream" and click Next
  - Export to the repo root: <clone-path>/system_wrapper.xsa
  - Click Finish

  7b. CRITICAL - Patch the GP1 APER_CLK Bug (Vivado 2025.2):
  ---------------------------------------------------------------
  Vivado does NOT enable the GP1 AMBA peripheral clock when M_AXI_GP1
  is used. Without this patch, ALL HDMI IPs (VDMA, VTC, dynclk) will
  hang silently because they are on GP1.

  After exporting XSA and updating the platform in Vitis (Step 10),
  open this file in the Vitis workspace:
    <workspace>/system_wrapper/_ide/psinit/ps7_init.tcl

  Search for register 0xF800012C (APER_CLK_CTRL). There are 3 occurrences.
  Bit 20 must be SET in the value field:
    WRONG:   mask_write 0XF800012C 0x01FFCCCD 0x01EC044D
    CORRECT: mask_write 0XF800012C 0x01FFCCCD 0x01FC044D

  Fix ALL 3 occurrences. Save the file.

  WARNING: Vivado may revert this patch on every XSA re-export.
  You MUST re-check and re-apply after every XSA update.
  ---------------------------------------------------------------

  STEP 8: OPEN VITIS AND CREATE A NEW WORKSPACE
================================================================================

  IMPORTANT: Do NOT open the existing my_vitis_ws/ directory in Vitis.
  It contains hardcoded paths from the original developer's machine.
  Always create a fresh workspace.

  - Open Vitis Unified IDE 2025.2
  - When prompted, create a NEW workspace in any location, e.g.:
      <clone-path>/fresh_vitis_ws
    (Do NOT point it at my_vitis_ws/)

================================================================================
  STEP 9: CREATE THE PLATFORM COMPONENT
================================================================================

  - File > New Component > Platform
  - Component name: system_wrapper
  - Click Next
  - For "Hardware Design (XSA)": Browse to:
      <clone-path>/system_wrapper.xsa

================================================================================
  STEP 10: BUILD THE PLATFORM
================================================================================

  - In the Component Explorer, select "system_wrapper"
  - Click the Build button (hammer icon)
  - Wait for the platform to build (generates BSP, FSBL, etc.)
  - This must complete successfully before creating the application.

  AFTER BUILDING: Apply the GP1 ps7_init.tcl patch from Step 7b.
  The file is now at:
    <workspace>/system_wrapper/_ide/psinit/ps7_init.tcl

================================================================================
  STEP 11: CREATE THE APPLICATION COMPONENT
================================================================================

  - File > New Component > Application
  - Component name: zybo_project
  - Click Next
  - Select platform: system_wrapper (the one you just created)
  - Click Next
  - Domain: standalone_ps7_cortexa9_0
  - Click Next
  - Template: Empty Application (C)
  - Click Finish

================================================================================
  STEP 12: ADD THE SOURCE FILES
================================================================================

  The source files are in my_vitis_ws/zybo_project/src/ in the repo.
  Copy the ENTIRE contents into the new application's src/ directory,
  preserving the folder structure. This WILL overwrite the default
  CMakeLists.txt and UserConfig.cmake that Vitis generated — that is
  intentional, because our customized versions add the subdirectory
  sources and include paths needed to build.

  Windows (PowerShell):
    Copy-Item -Recurse -Force <clone-path>\my_vitis_ws\zybo_project\src\* `
      <workspace-path>\zybo_project\src\

  Linux/Mac:
    cp -r <clone-path>/my_vitis_ws/zybo_project/src/* \
      <workspace-path>/zybo_project/src/

  This copies the following structure into your application's src/:

    Top-level files:
      demo.c               <-- Main application (spectrum analyzer logic)
      demo.h               <-- Application header
      platform.c, platform.h, platform_config.h
      lscript.ld           <-- Linker script
      xpar_remap.h         <-- SDT compatibility macros (REQUIRED)
      xtime_l.h            <-- Timer header (REQUIRED, missing from BSP)
      CMakeLists.txt       <-- Customized build config (MUST overwrite default)
      UserConfig.cmake     <-- CMake config with subdirectory sources

    Subdirectories (MUST keep folder structure):
      audio/audio.c, audio/audio.h       - SSM2603 codec control (I2C)
      display_ctrl/display_ctrl.c, .h    - HDMI display controller + VDMA
      display_ctrl/vga_modes.h           - Video timing modes (640x480)
      dma/dma.c, dma/dma.h              - AXI DMA configuration
      dynclk/dynclk.c, dynclk/dynclk.h  - Dynamic clock for pixel clock
      iic/iic.c, iic/iic.h              - I2C driver
      intc/intc.c, intc/intc.h          - Interrupt controller setup
      userio/userio.c, userio/userio.h  - Button/switch GPIO handling

  IMPORTANT: The copied CMakeLists.txt is customized to:
    - Add aux_source_directory for dynclk/
    - Add target_include_directories for all subdirectories
      (audio, dma, iic, intc, userio, display_ctrl, dynclk)
    - Link the math library (-lm) for sqrtf/logf in spectrum code
  If Vitis regenerates CMakeLists.txt, re-copy ours from the repo.

  After copying, right-click the project in Vitis and select Refresh.

================================================================================
  STEP 12b: VERIFY CMakeLists.txt AND UserConfig.cmake
================================================================================

  The default Vitis "Empty Application" only auto-collects .c files in
  the top-level src/ directory. Our project has sources in subdirectories
  that require two customized files:

  UserConfig.cmake must contain:
    set(USER_COMPILE_SOURCES
      "display_ctrl/display_ctrl.c"
      "audio/audio.c"
      "dma/dma.c"
      "iic/iic.c"
      "intc/intc.c"
      "userio/userio.c"
    )

  CMakeLists.txt must contain (in addition to the default content):
    - aux_source_directory for dynclk/ (dynclk.c is NOT in UserConfig)
    - target_include_directories for all 7 subdirectories
    - collect(PROJECT_LIB_DEPS m)  for math library (sqrtf, logf)

  Both files are already correct in the repo copy. If Step 12 was done
  correctly (full copy with overwrite), no manual edits are needed.
  If Vitis regenerates either file, re-copy from the repo.

================================================================================
  STEP 17: VERIFY OPERATION
================================================================================

  - Open a serial terminal (115200 baud, 8N1) on the board's COM port
  - You should see initialization messages and the main loop starting
  - Press BTN3 to start audio capture and spectrum display
  - The HDMI monitor should show:
      * Title "SPECTRUM ANALYZER" at the top
      * A reactive color bar across the top edge
      * 24 vertical bars split into 3 labeled groups: BASS, VOCAL, HIGH
      * Peak-hold dots floating above bars
      * Mirror reflections below the bars
      * Gradient dark background
  - Toggle SW0 to enable/disable audio passthrough to headphone out
  - Toggle SW1 to enable gain boost (1.5x) for quiet songs
  - Press BTN3 again to stop, BTN3 to restart

  If bars appear frozen or DMA stalls, the built-in watchdog will
  automatically restart the audio pipeline within ~2 seconds.

================================================================================
  BLOCK DESIGN ARCHITECTURE (key connections)
================================================================================

  Audio path (PL):
    SSM2603 Codec -> I2S Receiver -> Stereo-to-Mono Mixer ->
    Sample Buffer (BRAM) -> FFT IP Wrapper -> Xilinx FFT LogiCORE (256-pt) ->
    AXI Stream FIFO -> AXI DMA (S2MM) -> DDR via HP0

  HDMI path (PL):
    DDR (framebuffer) -> AXI VDMA (via HP2) -> AXI4-Stream to Video Out ->
    Video Timing Controller (VTC) -> rgb2dvi -> HDMI TX

  Control (PS via GP0):
    AXI GPIO (buttons/switches), AXI DMA control, I2C to codec

  HDMI IPs (PS via GP1 through axi_interconnect_hdmi):
    VDMA:   0x83000000
    dynclk: 0x83C00000
    VTC:    0x83C10000

  Memory port separation:
    HP0: Audio DMA (FFT data from PL to DDR)
    HP2: VDMA (framebuffer reads from DDR to HDMI)
    This prevents contention between audio and video paths.

================================================================================
  KNOWN ISSUES AND WORKAROUNDS
================================================================================

  1. GP1 APER_CLK Bug (Vivado 2025.2):
     Vivado does not set bit 20 in APER_CLK_CTRL for GP1. Must manually
     patch ps7_init.tcl after EVERY XSA export. See Step 7b.

  2. DMA Pipeline Stalls:
     The AXI-Stream pipeline can occasionally deadlock due to backpressure.
     A software watchdog in demo.c detects S2MM stalls and performs a full
     pipeline restart (fnStopAudio + fnStartAudio). Recovery is automatic
     but may cause a brief visual freeze (~1-2 seconds).

  3. v_axi4s_vid_out Async Clock:
     The AXI4-Stream to Video Out IP must have C_HAS_ASYNC_CLK=1 because
     the AXI clock (100MHz) and pixel clock (~25MHz for 640x480) are
     different domains. If this is set to 0, the HDMI monitor will show
     "no signal". This is already configured in the block design.

================================================================================
  SDT COMPATIBILITY NOTES (Vitis 2025.2)
================================================================================

  The original Digilent source code used the legacy HSI/SDK flow. Vitis 2025.2
  uses the System Device Tree (SDT) flow with different XPAR_ macro names.
  The file xpar_remap.h handles all necessary mappings.

  CRITICAL: SDT fabric interrupt IDs are SPI offsets, NOT GIC IDs.
    xpar_remap.h adds XSCUGIC_SPI_INT_ID_START (=32) to convert them.
    Without this, no fabric interrupts fire and the system appears dead.

  CRITICAL: DMA s2mm/mm2s interrupt ordering depends on the block design
    concat wiring. In this BD:
      mm2s_introut -> xlconcat_0/In2 -> XPAR_FABRIC_AXI_DMA_0_INTR
      s2mm_introut -> xlconcat_0/In3 -> XPAR_FABRIC_AXI_DMA_0_INTR_1
    If you change the BD wiring, update xpar_remap.h accordingly.

================================================================================
  SOFTWARE ARCHITECTURE (demo.c)
================================================================================

  Key constants:
    FFT_SIZE          256        256-point FFT
    USABLE_BINS       128        Nyquist limit (bins 0-127)
    NUM_BARS          24         Total display bars
    BASS_BARS         5          Bars for bass group (bins 1-4, ~187-750Hz)
    MID_BARS          10         Bars for vocal group (bins 4-35, ~750Hz-6.6kHz)
    HIGH_BARS         9          Bars for high group (bins 35-80, ~6.6-15kHz)
    NOISE_FLOOR       10.0       Magnitude threshold to suppress FFT noise
    MAG_SCALE         2.5        Divisor for height scaling
    SMOOTH_DECAY      0.7        Bar fall-off factor per frame
    PEAK_HOLD_FRAMES  12         Frames before peak dot starts falling
    PEAK_FALL_RATE    4          Pixels/frame peak dot falls

  Per-group gain normalization:
    Bass:  0.4x  (attenuated - bass naturally dominates FFT output)
    Vocal: 1.0x  (reference)
    High:  1.8x  (boosted - high frequencies have lower FFT magnitude)

  Rendering pipeline:
    1. DMA interrupt fires -> processFFTFrame() called
    2. Unpack 16-bit real + 16-bit imag from each FFT bin
    3. Compute magnitude: sqrt(re^2 + im^2) - NOISE_FLOOR
    4. For each bar: find peak magnitude in its bin range
    5. Apply per-group gain * user gain (SW1) / MAG_SCALE
    6. Smooth decay: bar falls at 70% per frame, rises instantly
    7. Peak hold: track max, hold 12 frames, then fall at 4px/frame
    8. Render to back buffer (double-buffered to prevent flicker):
       - Gradient background (dark top to slightly lighter bottom)
       - Main bars with brightness gradient (bright top, dark base)
       - Top glow (3px bright highlight at bar peak)
       - Mirror reflection (faded below baseline)
       - Peak hold dots (white)
       - Group labels: BASS, VOCAL, HIGH
       - Title: SPECTRUM ANALYZER
       - Reactive top color bar (blends group colors by energy)
    9. Cache flush + DisplayChangeFrame() to swap buffers

================================================================================
  QUICK REFERENCE / TROUBLESHOOTING
================================================================================

  Q: Vivado says "board part not found"
  A: Install Digilent board files from:
     https://github.com/Digilent/vivado-boards

  Q: Vivado says IPs are locked or need upgrade
  A: Reports > Report IP Status > "Upgrade Selected", then re-synthesize.

  Q: Synthesis fails with "Incremental checkpoint file does not exist"
  A: In Vivado Tcl console:
       reset_run synth_1
       set_property AUTO_INCREMENTAL_CHECKPOINT 0 [get_runs synth_1]
       launch_runs synth_1 -jobs 16

  Q: HDMI monitor says "No Signal"
  A: Three common causes:
     1. GP1 ps7_init.tcl not patched (most likely). See Step 7b.
     2. Bitstream not copied to Vitis _ide/bitstream/. See Step 13.
     3. v_axi4s_vid_out async clock misconfigured (should be C_HAS_ASYNC_CLK=1).

  Q: Bars all show zero / spectrum is flat
  A: Check UART output for FFT magnitudes. If raw DMA data is non-zero
     but bars are zero, NOISE_FLOOR may be too high. Current value: 10.0.

  Q: Display freezes then recovers after a few seconds
  A: This is the DMA stall watchdog doing its job. The AXI-Stream pipeline
     occasionally deadlocks. The watchdog restarts it automatically.
     Press BTN3 twice (stop + start) for immediate manual recovery.

  Q: Bass bars dominate / display is left-leaning
  A: Per-group gain normalization is tuned in demo.c (groupGain[] array).
     Adjust bass attenuation (currently 0.4x) or high boost (currently 1.8x).

  Q: Build fails with "undefined reference to fnInitIic" etc.
  A: UserConfig.cmake is missing subdirectory sources. See Step 12b.

  Q: App boots but buttons do nothing
  A: SDT interrupt ID issue. Verify xpar_remap.h has the
     "+ XSCUGIC_SPI_INT_ID_START" lines for all fabric interrupts.

  Q: Platform build fails with "XSA not found"
  A: Verify system_wrapper.xsa exists at the path you specified.
