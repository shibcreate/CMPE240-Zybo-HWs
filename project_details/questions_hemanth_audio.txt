CMPE240 - Hemanth's Section: Audio Input (I2S + SSM2603 Codec)
================================================================

Q1. How does the PS communicate with the SSM2603 audio codec, and
    what protocol is used for control vs data?

A1. Control uses I2C (Inter-Integrated Circuit) at slave address 0x1A
    to configure codec registers (volume, input source, sample rate,
    power management). Data uses I2S (Inter-IC Sound) which is a
    separate 3-wire serial protocol (BCLK, LRCLK, SDATA) handled
    entirely in the PL. The PS writes codec registers via I2C using
    fnAudioWriteToReg(), which sends 2 bytes: the register address
    shifted left by 1 with the MSB of data OR'd in, followed by the
    LSB of data. The actual audio samples flow through I2S in the PL
    and never touch the PS directly -- they go through the AXI-Stream
    pipeline to the FFT and then via DMA to DDR.

Q2. What is the I2S clock configuration, and is the codec running in
    master or slave mode?

A2. The codec runs in slave mode (R8 = 0b000000000). The MCLK at
    12.288 MHz is generated by a Clocking Wizard IP in the PL and
    fed to the codec. The sampling rate of 48 kHz is derived from
    this master clock (12.288 MHz / 256 = 48 kHz). In slave mode
    the codec does not generate its own clocks -- it receives BCLK
    and LRCLK from the I2S IP in the PL. The I2S_CLOCK_CONTROL_REG
    bits [2:0] set sampling rate parameters, and bit 16 would enable
    master mode, but we leave it at 0 for slave operation.

Q3. Walk through the codec startup sequence. Why is fnInitAudio()
    called twice?

A3. The startup sequence in fnAudioStartupConfig() is:
    1. Reset I2S controller
    2. Software reset codec (R15 = 0x00), wait 1 ms
    3. Power management enable (R6 = 0b000110000)
    4. Set ADC volumes (R0, R1 = 0b000010111, mid-range gain)
    5. Set DAC volumes (R2, R3 = 0b101111001, mid-high output)
    6. Configure analog/digital paths (R4, R5 = 0)
    7. Set digital interface to I2S mode (R7 = 0b000001010)
    8. Set sample rate to slave (R8 = 0)
    9. Wait 1 ms, activate codec (R9 = 1)
    10. Final power config (R6 = 0b000100000)

    fnInitAudio() is called twice with a 2-second gap between them.
    This is because the codec's internal PLL needs time to lock to
    the external MCLK. The first call starts the PLL, the delay
    lets it stabilize, and the second call re-initializes with a
    stable clock. Without this, the codec may output garbage or
    have incorrect sample timing.

Q4. How does the I2S IP interface with the DMA for audio recording?

A4. In fnAudioRecord(), the sequence is:
    1. XAxiDma_SimpleTransfer() sets up a DMA S2MM transfer to
       MEM_BASE_ADDR with byte count = 5 * numSamples (24-bit
       samples are packed into 32-bit words with padding)
    2. I2S_PERIOD_COUNT_REG is set to the number of samples
    3. I2S_TRANSFER_CONTROL_REG bit 1 (RX_RS) is set to start RX
    4. I2S_STREAM_CONTROL_REG = 1 enables the S2MM stream path

    The I2S IP captures audio samples at 48 kHz, packs them into
    AXI4-Stream transactions, and the DMA writes them to DDR in
    burst mode. When the transfer completes, DMA fires an interrupt
    to the PS via the GIC.

Q5. What register controls the input source selection, and what are
    the bit patterns for microphone vs line-in?

A5. Register R4 (Analog Audio Path Control) on the ADAU1761 codec:
    - Microphone input: R4 = 0b000010100 (enables mic boost + mic path)
    - Line input:       R4 = 0b000000010 (line-in, no boost)
    Our project uses fnSetLineInput() since audio comes from the
    3.5 mm line-in jack (J6). The mic input has a built-in preamp
    boost which would overdrive line-level signals.

Q6. What are the I2S register offsets, and what does each control?

A6. Base address = AUDIO_CTL_ADDR (mapped via AXI):
    +0x00  I2S_RESET_REG             - Soft reset
    +0x04  I2S_TRANSFER_CONTROL_REG  - bit 0: TX_RS (playback)
                                       bit 1: RX_RS (record)
    +0x08  I2S_FIFO_CONTROL_REG      - bit 30: TX FIFO reset
                                       bit 31: RX FIFO reset
    +0x0C  I2S_DATA_IN_REG           - RX data register
    +0x10  I2S_DATA_OUT_REG          - TX data register
    +0x14  I2S_STATUS_REG            - bit 0: TX empty
                                       bit 16: RX empty
    +0x18  I2S_CLOCK_CONTROL_REG     - bits [2:0]: sample rate
                                       bit 16: master mode enable
    +0x1C  I2S_PERIOD_COUNT_REG      - number of samples to transfer
    +0x20  I2S_STREAM_CONTROL_REG    - bit 0: S2MM enable
                                       bit 1: MM2S enable

Q7. Why does fnStartAudio() reset both TX and RX FIFOs before
    starting the stream?

A7. The I2S FIFOs operate in a different clock domain (audio clock
    at ~12.288 MHz) than the AXI bus (100 MHz system clock). If
    stale data is left in the FIFOs from a previous run, the L/R
    channel alignment can be wrong -- the system might start
    reading from the middle of a stereo pair, causing the left and
    right channels to swap. Resetting both FIFOs (bits 30 and 31
    of I2S_FIFO_CONTROL_REG) clears any residual data and ensures
    the first sample out is properly aligned to the left channel.

Q8. How does the gain boost work at the codec level?

A8. When the user presses BTN2, the software toggles between two
    volume settings on the codec:
    - Normal: ADC volume R0/R1 = 0b000010111, DAC volume R2/R3 = 0b101111001
    - Boosted: ADC volume = 0b000011111, DAC volume = 0b101111111
    These are written to the codec over I2C. The ADC gain affects
    how loud the input signal is digitized, and the DAC gain affects
    headphone output level. Additionally, the software applies a
    1.5x multiplier to the FFT magnitudes in spectrum.c for the
    visual gain boost on HDMI.

Q9. What is the audio data format on the AXI-Stream bus?

A9. The SSM2603 outputs 24-bit signed samples in I2S format. The
    I2S IP captures these and places them in the lower 24 bits of
    a 32-bit AXI-Stream word (upper 8 bits = 0). The stream is
    interleaved stereo: Left sample, Right sample, Left, Right...
    at 48 kHz per channel (96k samples/sec total on the bus).
    The data rate is 48000 * 24 * 2 = 2.304 Mbps raw audio, or
    48000 * 32 * 2 = 3.072 MHz on the AXI-Stream bus.

Q10. If the I2C write to the codec fails, what happens?

A10. fnAudioWriteToReg() has tolerance for I2C failures -- it
     returns XST_SUCCESS even if the exact byte count was not sent.
     This is intentional because I2C timing can vary and the codec
     may NACK occasionally during initialization. In contrast,
     fnAudioReadFromReg() is strict and returns XST_FAILURE if the
     byte count doesn't match. The rationale is that a failed write
     during init just means that register keeps its default value,
     which is usually acceptable, but a failed read would give
     corrupted data that the software might act on incorrectly.
